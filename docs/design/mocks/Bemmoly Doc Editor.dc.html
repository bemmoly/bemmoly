Auth service RFC
Priya N. · Created Sep 12 · Edited 2h ago·6 min read·Linked: PLT-204, PLT-218, PLT-222
TL;DRgenerated · updates with the doc
Move sessions from Redis to Postgres behind a flag; dual-write, cut reads, keep Redis warm 7 days. Rollback is a flag flip. Open question: flag TTL (15 vs 30 min).

Context

We're moving session handling out of the monolith into a standalone auth service. Sessions currently live in a Redis cluster with no durability guarantee; evictions under memory pressure have logged users out twice this quarter (see Postmortem: Sep 29 login outage).

Migration order

  1. Dual-write sessions to Redis and Postgres PLT-204IN REVIEW
  2. Switch reads behind auth_pg_sessions PLT-218IN PROGRESS
  3. Rate-limit the refresh endpoint before GA PLT-222TO DO
  4. Remove the legacy cookie path + Create issue from this line

Rollback

If error rates exceed 0.5% after cutover, flip auth_pg_sessions off. Sessions issued by the new service stay valid for 15 minutes, so users aren't logged out.

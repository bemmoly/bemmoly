# Translating Bemmoly

How text becomes translatable, for anyone adding a screen, a string or a language. The
decision and its reasons are [ADR 0024](adr/0024-i18n-lingui-catalogs-per-namespace.md); the
words themselves follow [content.md](design/system/content.md).

English is the source and, for now, the only language that ships. Everything people read comes
from a message catalog, so adding a language later is translation work, not code.

## Where text lives

One catalog per namespace and language, next to the code that draws it:

```
packages/core-web/src/i18n/core.en.json      the frame, page header, bottom bar
apps/web/src/i18n/shell.en.json              sidebar, menus, phone bar, sign-in
apps/web/src/i18n/settings.en.json           Settings (Profile so far)
packages/shared/src/i18n/errors.en.json      the server's default error messages
packages/core/src/services/i18n/email.en.json  emails (password reset so far)
modules/<id>/web/src/i18n/<id>.en.json       a module's own words, when it is extracted
```

A file is one flat JSON object of id → [ICU message](https://unicode-org.github.io/icu/userguide/format_parse/messages/).
Ids are `<namespace>.<area>.<name>` in camelCase: `shell.signIn.forgot`. Keys are kept sorted
(`pnpm i18n:extract` sorts them).

## Add a string

1. Write the English in the namespace's `<namespace>.en.json`, following content.md: sentence
   case, verbs on buttons, errors that say what to do next.

   ```json
   "shell.signIn.forgot": "Forgot password?",
   "work.backlog.count": "{count, plural, =0 {No issues} one {# issue} other {# issues}}",
   "shell.signIn.welcomeBack": "Welcome back, {name}. Opening {workspace}…"
   ```

2. Read it through the namespace's handle. In a component, `useT` re-renders when the language
   changes; the id is type-checked against the English file.

   ```tsx
   import { useT } from '@bemmoly/core-web';
   import { shellText } from '../../i18n/catalogs.ts';

   const t = useT(shellText);
   return <Link to="/forgot-password">{t('shell.signIn.forgot')}</Link>;
   ```

   Outside React (a toast, a hook's message) call `shellText.t('…')`.

3. Rules of thumb:
   - **One sentence, one message.** Never build a sentence from pieces (`t('a') + name +
     t('b')`); pass values instead (`{name}`), since word order changes between languages.
   - **Plurals are ICU**, never `count === 1 ? … : …`. Numbers inside messages are formatted for
     the locale (`#`, `{n, number}`).
   - **Links and emphasis inside a sentence** use tags and `t.rich`:

     ```tsx
     t.rich('shell.signIn.rateLimitedBody', { wait }, {
       link: (text) => <Link to="/forgot-password">{text}</Link>,
     });
     ```

   - **Dates, times and numbers** go through the helpers, never `toLocaleString('en')`:
     `RelativeTime` / `formatRelative`, `formatAbsolute`, `formatDate`, `formatDateTime`,
     `formatNumber`, `formatBytes` (from `@bemmoly/core-web`). They follow the person's language.
   - **Product names** (Bemmoly) stay literal. Data (a project's name, a person's name) is never
     translated.
   - **Layout** uses logical utilities (`ms-`, `pe-`, `start-`, `end-`, `border-s`, `rounded-e`,
     `text-start`) so it mirrors in a right-to-left language.

4. `pnpm typecheck` and `pnpm i18n:check` catch an id that is not in English.

## Add a namespace (a module, or a new area)

```ts
// modules/work/web/src/i18n/catalog.ts
import { defineCatalog } from '@bemmoly/core-web';
import source from './work.en.json' with { type: 'json' };

export const workText = defineCatalog('work', source);
```

Import the handle only from code inside the module's chunk, so its words load with it. Every id
in the file must start with the namespace (`work.`). The kernel never imports a module's
catalog; registration happens when the chunk runs.

Server text uses `serverText(locale)` from `packages/core/src/services/i18n`, with the same
layout. Errors keep their English `message` and name the catalog message with `messageId` (and
`values`) when it should be shown translated:

```ts
throw new ConflictError('That key is taken', {
  messageId: 'work.projects.keyTaken',
  values: { key },
});
```

## Extract an existing screen

1. Move its strings into the namespace's English file and read them with `t`.
2. Turn physical classes into logical ones.
3. Add the file to the extracted list in `eslint.config.js` (or `packages/core-web/eslint.config.js`):
   from then on `bemmoly/no-literal-ui-strings` and `bemmoly/logical-properties` fail any new
   literal or physical class there.
4. Look at it in the pseudo-locale: open the screen with `?locale=en-XA`. Every extracted word is
   accented, about 40% longer and bracketed (`[Šíĝñ íñ ···]`). Plain English left on screen was
   missed; a missing closing bracket means the text is clipped. Add the screen to
   `apps/web/e2e/pseudo-locale.spec.ts` if it is part of the frame or a main flow.

The pseudo-locale stays on for this device until you pick a language in Settings › Profile (it is
listed there in dev builds) or open a page with `?locale=en`.

## Add a language

1. `pnpm i18n:extract --locale fr` writes `<namespace>.fr.json` beside every English catalog, with
   every id and empty messages. Translate them (keep every `{placeholder}` and `<tag>` as it is
   in English).
2. Register the lazy loader in each `defineCatalog` call:

   ```ts
   export const shellText = defineCatalog('shell', shellSource, {
     fr: () => import('./shell.fr.json', { with: { type: 'json' } }),
   });
   ```

   For server namespaces, add the file to `TRANSLATED` in `packages/core/src/services/i18n`.
3. While the catalogs are incomplete, the language is not offered; English fills any gap. Test it
   with `?locale=fr`.
4. To ship it, add it to `SHIPPED_LOCALES` in `packages/shared/src/i18n/locales.ts`. From then on
   `pnpm i18n:check` (run in CI) fails if any of its catalogs lacks an id, and Profile and
   Settings › Workspace offer it, named in its own words.
5. A right-to-left language also needs the remaining physical classes, pointing icons and slide
   motion mirrored across the product before it ships (ADR 0024, item 9).

## Commands

| Command                            | What it does                                                                                 |
| ---------------------------------- | -------------------------------------------------------------------------------------------- |
| `pnpm i18n:check`                  | The CI gate: ids, ICU syntax, one source per namespace, shipped locales complete, placeholders match English, every id the code names exists |
| `pnpm i18n:extract`                | Sorts every catalog and lists ids the code uses that have no English yet                    |
| `pnpm i18n:extract --locale <tag>` | Also writes that language's catalogs beside the English ones, new ids empty, stale ids gone |
